# 物资产出配额 · 1.1.40

日期：2026-09-27

## 交付行为

在 Mod Menu → 开箱管理 → 选择箱子 → 物资产出配额，分别设置白、蓝、紫、金、红的统计周期和数量上限。每种品质可单独选周/月；各箱独立，全服玩家共享。-1 不限、0 停产。五色进度条显示已产出、上限、剩余与待完成开箱预占量；小窗口支持翻页和滚轮。

限制按实际数量执行：皮肤每件按注册品质计数，苹果和角色卡按照现有公开奖池的白色品质计数，80 个苹果占 80 个额度、3 张卡占 3 个额度。满额品质暂停本箱对应候选，其他品质和其他箱子仍可产出。额度不足整份奖励时不拆分，无法完成本次所有抽取时整次不扣箱钥、不发部分奖励。

周和月分别记录，选择周期仅决定执行哪个上限。修改额度、切换周期或服务重启不会清零。UTC 周一 00:00 / 每月 1 日 00:00 重置，即北京时间 08:00；月份为自然月，不再与周额度强制保持四倍关系。

## 持久化与兼容

- schema 5 新增各箱 `outputLimits`、`outputWeeklyUsed`、`outputMonthlyUsed` 和事务 `outputDelta`。
- 旧全服周品质上限复制为各箱初始周额度。旧月全服限制和开箱次数限制停止执行；旧使用量/次数不能准确按箱和品质拆分，新计数从升级后开始。原资产、旧统计及未完成开箱记录保留。
- 旧待完成事务从已记录的皮肤品质、苹果数量和卡片数量恢复物资预占。跨周期只写入与原事务窗口一致的计数。
- 服务端在抽奖期间预扣本次暂存额度，落盘 intent 后预占给其他请求，结算提交后一次转为已产出。写入失败或提交异常恢复计数快照；重复请求使用原收据。
- 配置保存仅接受设置，忽略客户端提交的计数和事务内容。编辑时每五秒继续刷新真实用量，保留未保存输入。
- 保存通道升级到 v5；旧编辑器收到升级提示，不能把不了解的新配额重置。客户端和服务端应一起更新。
