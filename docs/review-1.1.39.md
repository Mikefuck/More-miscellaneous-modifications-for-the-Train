# 开箱保存与统一奖池修复 · 1.1.39

## 范围

按 Mike 的后续澄清，跳过“开箱页面内容列表与 Mod Menu 不同”的审查；本次没有修改开箱预览页面或其候选列表。处理保存、概率规则和两个奖励池合并。

## 原因与处理

1. 原服务端配置权限仅检查 OP。未开启作弊的单人房主也会被拒绝。现在开箱管理允许单人世界房主；局域网客人、专用服务器玩家仍需 OP 和菜单授权，服务端继续校验每次保存。
2. 原保存按钮依赖其他网络功能缓存的 `ClientLotteryState.op`，且管理页不在每个 tick 更新保存状态。现在使用开箱配置请求自身的授权结果；权限或连接状态变化时刷新，底栏说明离线、只读、无修改、未保存或保存结果。没有实际修改时按钮禁用属于正常行为。
3. 配置修订冲突会保留旧草稿，但原提示要求重试，重试仍携带旧修订号。现在显示冲突，提供“重新载入服务端设置”；用户确认后才丢弃未保存内容。写入失败也保留草稿。
4. 旧 `skin_plus_bonus` 将皮肤权重与物品独立概率分开计算。皮肤的 100% 只是皮肤池内部占比，物品仍可另外产出。现在只能保存统一权重规则，皮肤、苹果、卡片一起竞争，每抽获得一项奖励，默认每箱一抽。

以上是源码确认并覆盖测试的故障路径；未读取用户实际游戏目录或存档，不能凭截图断定当时唯一触发原因。

## 使用与迁移

- 权重为相对值：单项权重 / 所有有效奖励权重。只有一个皮肤权重大于零时，10、100 等正权重都对应基础概率 100%。
- “只抽此奖励（100%）”保留该奖励正权重，将其他奖励设为零，并将每箱抽取次数设为一。零权重条目仍显示在编辑器内，方便重新启用。
- schema 4 首次升级固定旧自动品质池。旧独立物品概率百分数四舍五入成权重，例如 50% → 50、0% → 0，正概率最低权重为 1。保留皮肤权重和奖励数量，旧皮肤抽取次数为零的皮肤继续停用。
- 旧双池改为每箱一抽；已有统一池保留抽取次数，取消皮肤保底。空池停用，避免阻塞其他箱子的保存。资产、产出记录、未完成的开箱事务继续保留。
- 配额、皮肤提供者缺失、未拥有优先和重复限制仍影响可抽范围；100% 是当前基础单抽概率，不会绕过产出限制。
