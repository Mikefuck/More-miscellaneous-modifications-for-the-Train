# 哈比列车抽奖补齐 (habitrain_lottery)

Fabric 1.21.1 账户功能模组。当前版本提供独立皮肤目录与皮肤特效 API、绿苹果账户货币、角色卡、称号、邮件、每日任务、登录月历和账户仓库。

## 功能边界

- 绿苹果是本模组自己的账户货币，可通过每日任务、开箱、商店、邮件、管理员命令和公开玩家 API 增减。登录不会自动开始领取奖励；已申请但被写入故障中断的奖励会在重试或下次登录时恢复。
- 上游的**账户金币**在本模组加载后只减不增：胜负结算、升级、巫师 / 亡灵之主 / 操纵师事件与旧抽奖折算等所有游戏内发放都被关闭，仅保留维修模式职业解锁的扣费；余额仍以网站端数据库为权威源。
- 角色卡、称号、皮肤解锁与装备、特殊系统道具都保存到世界目录，不依赖上游数据库。
- Mod Menu → 哈比列车抽奖补齐 → 自选卡设置 → 管理自选卡可选角色：OP / 单人世界房主可开关角色限制、按名称或 ID 搜索、逐角色或批量允许 / 禁止自选，保存到服务器后立即影响新的选择。默认全部允许，外部 API 新角色自动加入列表；关闭总开关会保留逐角色设置。已预约自选及普通阵营卡不受影响。配置保存于 `<世界>/habitrain_lottery/config/self_select_roles.json`，角色别名 / 替换按 core 的有效目录解析，不可用角色的禁用设置保留。多人编辑冲突会拒绝覆盖；取消 / Esc 放弃草稿。配置损坏且无法从 `.bak` 恢复时暂停新的自选，修复后重启世界。
- 皮肤由扩展模组通过 `habitrain_lottery_skins` 入口点注册；本模组不内置皮肤内容。
- 支持独立背部皮肤（`back`）：衣柜分类按钮、背面 3D 预览、装备与恢复默认，外观同步给附近玩家；扩展接入示例见 [皮肤 API](docs/skin-api.md)。
- 邮件支持绿苹果、角色卡、自选卡、突破上限卡、皮肤、箱子与钥匙附件。领取使用持久化意图及各资产文件内的回执，失败后继续未完成步骤，已到账附件不会因重试而再次发放。邮箱按条数和内容大小分页。
- 邮件「按名字发送」支持在线与离线玩家，多名收件人可用换行、空格、逗号或分号分隔。离线邮件与附件保存在玩家 UUID 对应的邮箱中，上线后手动领取；正版服需要能解析账号 UUID，解析失败会在聊天栏提示。离线模式服请填写准确玩家名（包括大小写）。
- 每日任务由世界配置 `config/daily_tasks.json` 定义，可在管理页编辑。默认「每日登录」奖励为 160 绿苹果，可修改或停用；扩展模组也可通过 API 注册任务。
- 仓库只展示账户奖励，不读取玩家背包、末影箱或世界容器。
- 开箱管理支持每个箱子分别设置白、蓝、紫、金、红五种品质的周/月物资产出上限，并显示已产出、剩余和预占进度；按实际发放数量计数。详见 [开箱目录与配额](docs/crate-catalog.md)。

旧金币、抽数、兑换、奖池和抽奖终端已从本模组移除。旧玩家 JSON 中的这些字段会在服务器启动时删除，余额不会转换成绿苹果；旧邮件中的相应奖励会被忽略，其他附件仍可领取。

登录奖励在 1.1.29 改版：旧的「每日登录白送 4 张阵营卡」和「连续登录自动发绿苹果」都已取消，统一为每日任务终端上的内置任务「每日登录」（160 绿苹果，登录后手动领取）。每日阵营卡的 4 次/天使用上限与突破上限卡机制保持不变。

## 安装与构建

运行环境：Minecraft 1.21.1、Fabric Loader、Java 21、Fabric API、StarRailExpress 4.3.x 和 `habitrain_core >=2.0.19`。

```text
mods/
  habitrain_lottery-1.1.60.jar
  star_rail_express-4.3.0.jar
  habitrain_core-2.0.19.jar
```

```powershell
.\gradlew.bat build --no-daemon
```

`assemble` 会把最终 jar 复制到项目旁的 `临时` 目录。`check` 还会验证独立皮肤目录没有重新依赖上游实现或旧资源。

## 启动前更新与自动重启

安装 AutoModpack 4.0.x 后，客户端在游戏启动前提供服务器整合包选择窗口。成功安装并确认文件实际发生变化后，会自动关闭旧游戏，等待旧 Java 进程完全退出，再使用本次启动的 Java、内存设置与游戏参数重新启动。是否可自动重启按实际 Java 入口判断：标准 Fabric `KnotClient` 入口可尝试还原，启动器包装入口（例如 Prism/MultiMC 的专用入口）、调试启动或游戏/Fabric 版本变更则自动回退到退出。重启后的游戏是独立进程，原启动器可能显示原游戏已结束；它的日志窗口、运行状态和关闭联动不保证继续跟踪新游戏。

从成功安装完成时开始，5 分钟内启动游戏会跳过此选择窗口及启动时的联网更新，只加载已安装的整合包；重复启动不会重新计时。超过 5 分钟恢复原来的窗口规则。检查后无需更新、取消下载或安装失败都不会生成新的免弹窗记录。记录在 `config/habitrain_prelaunch_state.json`，窗口开关仍由 `config/habitrain_prelaunch.json` 的 `enabled` 控制。

1.1.61 起，更新检查直接校验文件内容的 SHA-1，不依赖缓存哈希；安装后再次检查下载是否完整，并比较安装前后的文件内容与路径。没有实际文件、整合包选择或游戏/加载器版本声明变化时继续进入游戏，不因完成回调或清单格式变化退出。切换到已缓存的另一个整合包也会触发一次重启。标记为可编辑的现有文件保留玩家修改，缺失文件仍会补齐。跳过更新和 5 分钟免弹窗路径使用相同的安装处理，不进入 AutoModpack 原有的阻塞退出窗口。

如果无法自动重启，会显示 5 秒提示后自动正常退出，玩家可回到当前使用的启动器重新启动，以便重新生成启动参数。独立重启程序最多等待旧进程退出 90 秒，超时不再创建新游戏；创建新进程后监测前 10 秒的非零退出，发现失败时提示并自动结束，不重复拉起。进程存活检查不能证明已经进入游戏主菜单，10 秒后的游戏崩溃仍需按普通游戏崩溃排查。自动重启诊断见 `logs/habitrain-restart.log`，新游戏的进程输出见 `logs/habitrain-restarted-game.log`，游戏自身仍写入 `logs/latest.log`。重启参数通过匿名管道传递，不另存含登录凭证的脚本。

本逻辑不按启动器品牌作兼容承诺；不同版本、临时原生库目录清理、登录代理和启动器的子进程管理都可能影响独立重启。PCL、HMCL、Prism/MultiMC 等真实客户端的主菜单、账号连接和启动器联动体验仍需分别实测。

## 世界数据

```text
<world>/habitrain_lottery/
  players/<uuid>.json
  mail/players/<uuid>.json
  backpack/players/<uuid>.json
  records/
  titles/
  reward-deliveries/<uuid>/<transaction>.json
  faction-refunds/<uuid>/<activation>.json
```

玩家主文件只保存绿苹果、皮肤状态、登录状态、任务进度、去重键和其他仍在使用的账户资产。写入失败会恢复内存快照并返回失败结果。

备份时应保存整个世界账户目录，保留奖励意图和回执。旧版本遗留的处理中邮件、没有卡牌回执的未提交开箱无法证明哪些奖励已经到账，会保持锁定并在日志记录，需管理员核对后恢复；不能直接删除标记重新领取。

阵营卡退款按每次用卡的独立编号持久化，旧退款不会覆盖下一次退款。启动和玩家登录时都会重试未完成退款；旧版 `faction-refunds/<uuid>.json` 仍会独立恢复。

## 管理命令

命令根为 `/hlt`，`/habitrain_lottery` 是同义别名。

- `/hlt green_apples <player> <amount>`：按增量调整绿苹果。
- `/hlt system_item <player> <namespace:item> <amount>`：发放特殊系统道具。
- `/hlt inspect <player>`：查看绿苹果、皮肤解锁数量和当前装备。
- `/hlt skins`：打开皮肤衣柜。
- `/hlt skins unlock|lock <players> <type> <id>`：管理皮肤解锁状态。
- `/hlt skins reregister`：重新运行皮肤扩展注册器。
- `/hlt mail`：打开管理员邮件撰写页。
- `/hlt mailbox`：打开玩家邮箱。

修改账户、邮件和皮肤的命令需要 OP；专用服务器还需要核心的 MenuGate 授权。
